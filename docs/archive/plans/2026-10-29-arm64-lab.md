# ARM64 lab implementation plan

> Historical record. This document describes its original implementation stage. See the [current documentation](../../README.md) for deployment and operating instructions.

Goal: replace double x86 emulation with an ARM64 Linux host in Lima/VZ,
retaining real Nova, Neutron L3/OVS, Boundary and OpenBao certificate SSH.

Approved design: the conversation's ARM64 proposal, with automatic QEMU
fallback on M1/M2. The Linux VM owns OpenStack and a rootful Docker daemon;
the controller, worker, database and OpenBao remain separate containers.
Existing Docker Desktop state is retained as the legacy backend.

Constraints: preserve the requested subnets; no ServiceNow or external
identity integration. Only loopback ports are forwarded to the Mac. Never
reuse an x86 disk as ARM64 or delete the old disk/volumes. Confirm KVM by
actually initializing an ARM vCPU, not just checking a device exists.

- [x] Add backend selection and a Lima lifecycle module. Default new commands
  to Lima, use `.state/lima` for backend-specific keys and VM configuration;
  `LAB_BACKEND=legacy` retains the previous CLI. Test M1/M2/M4 selection,
  explicit overrides, paths with spaces, and remote Compose environment.
- [x] Add Lima bootstrap, isolated service Compose configuration, provider
  bridge hookup and management address `172.20.2.15`. Test rendered Compose
  and shell syntax. Docker and OpenStack live in the VM's native disk.
- [x] Detect working KVM in Linux, render Nova settings for KVM or TCG,
  provision ARM64 UEFI images and verify the actual domain accelerator.
- [x] Install and boot Lima on this M4. Run OpenStack installation,
  provisioning and `./lab verify`, including certificate rejection tests.
  Record any limitations with evidence. Update README and infrastructure
  diagram for both backends.

Review focus: Docker Desktop sockets must never leak into Lima commands;
provider traffic must cross OVS/L3 with the original worker source; restarts
must retain disks/CA and reconnect bridges; unsupported nested virtualization
must select TCG; new host keys must not collide with legacy known_hosts.

Execution: in place, using the existing workspace and authorized scope.
No Git commits are possible under the current read-only .git permission.

Validation on 2026-10-30: OpenStack installed on M4/macOS 15.3.2 with Lima 2.2.1; an ARM64 UEFI KVM tenant booted; full laptop Boundary/certificate SSH passed with worker source 100.64.10.10. Provider peer, unsigned key, wrong principal, expired certificate, unauthorized signing principal and excessive TTL were rejected. Offline suite: 38 tests, one integration skip. Stop/start preserved the CA fingerprint and tenant disk; full verification passed after service recovery. An intermittent stale Neutron RPC startup led to a bounded one-shot recovery added to resume.sh. M1/M2 physical validation remains unavailable.

Final readiness checks also require the expected qrouter namespace and a running libvirt domain, avoiding stale API readiness after reboot. Recovery with these checks succeeded against the rebooted cloud.
